1. Problem and Motivation

Mittelstand workshops in the DACH region rarely run production machine learning, even though they hold three classes of data that an ML system can act on every day: customer reviews, product catalogues, and quality-control camera feeds. The blocker is the operational layer: registering, serving, monitoring, retraining, and isolating models across tenants. Werkstatt AI delivers that layer as a single platform, federating three Liora projects that each solve a real workshop-floor question.

Capstone bet. Modul 2 is graded on MLOps competency, not on a fourth ML model. Building one more model adds no new evidence; productionising three exercises every Modul 2 learning objective in one deliverable.

2. Federated Modules

Tier 1 CPUTabular

Module A: Customer Satisfaction

Source: project #2 Olist (02_supply_chain_csat). Binary classifier on post-purchase tabular data. Answers "is this customer about to leave a bad review?".

Latency budget: 200 ms p95.

Tier 2 GPUMultimodal

Module B: Catalogue

Source: project #6 Rakuten (06_rakuten_multimodal). Late-fusion vision plus text classifier. Answers "what is this part?" from a phone photo plus a title.

Latency budget: 800 ms p95.

Tier 3 GPUVision

Module C: Anomaly

Source: project #7 Industrial Anomaly (07_industrial_anomaly). Patch-distribution-based unsupervised anomaly detector. Answers "is this casting defective?" with a heatmap.

Latency budget: 1.5 s p95.

Why these three. They are deliberately heterogeneous. CPU-only, small-GPU, and full-GPU. Tabular, multimodal, vision-only. 100 ms, 800 ms, 1.5 s. A platform that handles all three without three separate stacks is the operational definition of platform leverage.

4. The Five-Endpoint Contract

Every federated module exposes the same five endpoints and emits the same metrics labels. One alert rule set covers the platform.

GET  /healthz       liveness
GET  /readyz        readiness, includes model load check
GET  /metrics       Prometheus exposition
POST /predict       inference, takes tenant_id from JWT
GET  /model/info    current model URI and stage

Shared metrics schema

werkstatt_requests_total{module, tenant, tier, outcome}
werkstatt_request_latency_seconds_bucket{module, tier}
werkstatt_prediction_confidence_bucket{module}
Why fixed labels matter. One Grafana dashboard parameterised by $module covers all three. One alert rule set covers all three. Adding a fourth module adds zero new dashboards.

5. Train, Validate, Promote, Smoke-Test

Each module has one Airflow DAG with the same six tasks: extract, validate, train, evaluate, register, smoke-test. Promotion is gated on metrics; smoke-test verifies the live service has picked up the new version.

extract --> validate --> train --> evaluate --> register --> smoke_test --> drift_resolved | gate (e.g. ROC-AUC >= 0.78) | fail --> alert, do not promote

The smoke test calls /model/info on the live service after promotion. If the version has not incremented, the promotion is rolled back. This closes a class of "deployed but not live" failure that Paleyes 2022 cites as common in production ML.

6. Drift Loop

PSI (Population Stability Index) per feature on a one-hour rolling window. Threshold 0.25 sustained for 30 minutes triggers a retrain DAG. Drift is a trigger, not a verdict; the gate decides whether to promote.

[Live request] --> [Module] --> [feature snapshot] | [PSI hourly job] | PSI > 0.25, sustained | [Alertmanager -> Airflow trigger] | [Retrain DAG starts] | [pass / fail logged] | [auto-promote on pass]

PSI was chosen over Kolmogorov-Smirnov because it remains interpretable across numeric and categorical features. Reference: Lu et al 2018, Gama et al 2014, Bifet and Gavalda 2007, Losing et al 2018.

GPU-tier cascade

Inference uses confidence-thresholded escalation:

  1. Tier 1 (CPU). Cached predictions, simple sklearn (Module A baseline). Free.
  2. Tier 2 (small GPU). Quantised CNN, small batch (Module B). Used when Tier 1 confidence is low.
  3. Tier 3 (full GPU). Full-precision anomaly model (Module C). Used only when Tier 2 cannot decide.
Note. Cost figures above are budgeting estimates for Phase 1, not measurements. Actual run-rate will replace them after one month of Production traffic.

9. What the Federation Does Not Do

  • It does not fix model quality. If Module C reports a high false-positive rate on a customer's specific casting alloy, the platform makes that visible but does not solve it. The fix is per-module retraining with augmented data.
  • It does not address model-level information leakage from a shared cross-tenant model. Federated learning (Yang 2019) is the principled defence; it is not in Phase 1 scope.
  • It is not yet bit-for-bit reproducible. Phase 2 adds feature-snapshot persistence and seed pinning.
